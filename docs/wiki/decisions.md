# Decisions
- **D1** live-build + Docker rather than a handmade debootstrap: standard, reproducible ISO tooling.
- **D2** Live ISO first; installer (Calamares) is a stretch goal.
- **D3** i386 via `includes.chroot_before_packages/var/lib/dpkg/arch` so 32-bit exes work. UNVERIFIED that live-build applies it before the first apt update; fallback: a bootstrap-stage hook or `lb config --apt-options`.
- **D4** apt removed in the last chroot hook; dpkg retained.
- **D5** Terminal kept but renamed "Command Prompt" (agents/users need an escape hatch).
- **D6** Self-test is a systemd unit gated on kernel cmdline `winedows.selftest`; inert in normal boots.
- **D8** Browser is Firefox ESR branded "Edgy" with an Edge user-agent override. Real Microsoft Edge is NOT bundled: it only comes from Microsoft's apt repo and redistributing the binary in a public ISO likely violates its license.
- **D7** Autologin as `user`/`live` (live-config defaults).
- **D9** Project website is `docs/index.html` (static, `.nojekyll`). Enable Pages with "Deploy from branch → /docs". Download button fetches the latest GitHub Release via the API client-side; handles split ISOs.
- **D10** `docs/logo-mark.svg` is a compact, text-free mark (four panes, simplified glass/grapes/swoosh) for the site navbar and favicon; PNG exports at 16/32/48/64/180/256 and a multi-size `favicon.ico` next to it. The full `logo.svg` with the wordmark stays for the hero and the ISO.
- **D11** `user-setup` is listed explicitly: live-config only Recommends it and we build with `--apt-recommends false`, so without it no live `user` exists (no autologin; selftest `su user` fails). Run 21 showed wine64/wine32=FAIL within seconds of boot.
- **D12** Desktop CI test (`winedows.guitest`) is a second QEMU boot to graphical.target; it simulates the double-click with `gio open` in the session env rather than injecting mouse events (no xdotool in the image: Golden rule 2), and saves a QEMU screendump for eyeballing.
- **D13** Wallpaper set for rotation: 10 SVGs (R picked from 12: dropped panes and horizon, Bedrock is best so it is `01-` and the default; file order is rotation order) in `/usr/share/winedows/wallpapers/` (`build/config/includes.chroot/...`), generated by `scripts/gen-wallpapers.py` (stdlib, fixed seeds; edit the script, not the SVGs). Shared style: brand palette (navy, blue #0a4fd6, wine #9c1d3f), the logo mark in every one, the same "GigaHard Winedows / Linux, but it works." chip at bottom right above the panel. All artwork drawn in the script, except Linux Torvalds, who is the existing `docs/linux-torvalds.png` embedded. Slideshow wiring (Cinnamon `org/cinnamon/desktop/background/slideshow`) is done by the build, not here.
- **D14** (R, after the first USB hardware test) No terminal and no taskbar. `gnome-terminal` and the Command Prompt launcher are gone (supersedes D5); Cinnamon runs with `panels-enabled=[]`; Desktop icons are the only launcher (Wi-Fi icon opens `cinnamon-settings network`, falling back to `nm-connection-editor`; `cinnamon-control-center` added for it). No minimize button, since there is nowhere to minimize to. `winver` removed (unreachable); the Linus easter egg moved into the Desktop exe.
- **D15** Debian is invisible to users: PRETTY_NAME "GigaHard Winedows", /etc/issue, wallpaper, boot menu. GRUB is themed by `9000-winedows-bootmenu.hook.binary` (rewrites `set theme=`, renames entries, and appends an unconditional `set theme` to grub.cfg because live-build only sets it in some branches). Assets come from `includes.binary/` (pre-rendered PNGs: GRUB cannot render SVG and the builder has no SVG renderer).
- **D16** Edgy theme via Firefox autoconfig + agent stylesheet rather than an unsigned theme XPI (ESR signature rules) or a preseeded profile (dedicated profiles would ignore it). Window borders are a metacity-1 theme we drew ourselves (parody look, no third-party artwork).
- **D17** (R) Wallpapers rotate in random order every 5 minutes; cinnamon-slideshow advances right after login, so the first wallpaper is random too (an earlier autostart that set `picture-uri` itself made the slideshow disable itself; removed). The CI slideshow check allows up to 200 s since random order can repeat once.
- **D18** First-login Wine prefix is created with no display (`DISPLAY= wineboot -u` in `winedows-prefix.desktop`) so Wine's "configuration is being updated" dialog never pops up over the desktop (seen in run 24 screenshots).
