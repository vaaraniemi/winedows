# Testing
`make test` extracts the versioned `/live/vmlinuz-*` + `/live/initrd.img-*` (found with xorriso -find) from the ISO and boots QEMU headless with
`boot=live ... console=ttyS0 systemd.unit=multi-user.target winedows.selftest`. `winedows-selftest.service` (conditioned on that cmdline flag) writes to ttyS0:
`SELFTEST apt=absent`, `wine64=ok`, `wine32=ok`, `mime=ok`, then `WINEDOWS_SELFTEST_DONE`. `scripts/smoke-test.sh` greps `out/serial.log`. On a Wine failure the selftest also prints `SELFTEST diag <check>:` lines (tail of Wine's output, or a missing `user` account); the log is uploaded as the `serial-log` CI artifact.
Without KVM it is slow (up to ~15 min).

`make guitest` (`scripts/gui-test.sh`) boots the full graphical target with autologin and `winedows.guitest`. `winedows-guitest.service` waits for the user's `cinnamon` and `nemo-desktop` processes, then opens the Desktop .exe with `gio open` inside the session's environment (the same default-app lookup a Nemo double-click does) and checks the exe's Wine process appears. It prints `GUITEST cinnamon=ok`, `desktop-icons=ok`, `exe-open=ok`, `panels=none` (no taskbar), `wmtheme=ok` (no Muffin theme load error), `edgy=ok` (browser starts), `slideshow=ok` (slideshow delay set to 1 minute, the wallpaper URI must change and the slideshow must still be enabled), then `WINEDOWS_GUITEST_DONE`. Screenshots via the QEMU monitor, taken when the guest prints `GUITEST screenshot=<name>`: `out/bootmenu.png` (a separate BIOS boot of the ISO, GRUB menu), `out/desktop.png` (Linus window open), `out/edgy.png` (browser), plus `out/final.png`. The unit uses `KillMode=process` so the apps it opened survive the test script exiting (otherwise systemd closes them before the last screenshot). Before opening the exe it waits for first-login Wine setup to finish, like a person would. They are uploaded with the `serial-log` CI artifact and attached to every release as `screenshot-*.png`, so agents can look at them (artifact blob downloads are blocked in the agent sandbox; release assets are not). It does not move a real mouse, so Nemo's own click handling is still checked by eye or with `make vm`.

`make test` also checks (before booting) that the ISO's GRUB config loads `/boot/grub/winedows/theme.txt` and no menu entry says Debian, and the selftest adds `terminal=absent`, `branding=ok` (no Debian in issue/PRETTY_NAME/wallpaper/start page; Firefox renamed Edgy) and `desktop=ok` (Edgy, Wi-Fi and the exe present, no Command Prompt, exes not executable).
